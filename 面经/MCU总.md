3、FreeRTOS 
**FreeRTOS 里的 tick 是什么？双MCU的 STM32 和 ESP32 工程里，1 个 tick 分别是多少时间？**
```
tick 是 FreeRTOS 的系统时间节拍，不是 CPU 主频时钟。内核通过 tick 计数实现延时和超时。我的 STM32 工程 1 tick 是 1 ms，ESP 工程 1 tick 是 10 ms。
```

**`vTaskDelay()` 和 `vTaskDelayUntil()` 有什么区别？为什么你的 10 ms 电机控制任务更适合用 `DelayUntil`？**
```
vTaskDelay() 是从当前时刻开始相对延时，会把任务执行时间叠加进去；vTaskDelayUntil() 是按照固定的绝对节拍唤醒，更适合周期任务。我的电机控制任务要求 10 ms 固定周期，所以使用 delay-until 思路。
```
`vTaskDelay()`：**从现在开始等多久**  
`vTaskDelayUntil()`：**等到下一个固定时间点**

## 通信
1、UART、SPI、I²C、CAN 有什么区别？
```
UART 一般是点对点、异步通信，简单、调试方便；
SPI 是同步通信，速度高，通过 CS 选择不同从机；
I²C 也是同步通信，只需要 SCL 和 SDA 两根线，通过地址区分多个设备，速度一般比 SPI 低；
CAN 是多节点总线通信，支持仲裁和错误检测，抗干扰能力更强，但还需要 CAN 收发器和终端电阻。
```

2、CAN
```
CAN 是汽车电子常用的多节点总线通信协议，通过 CAN_H 和 CAN_L 两根差分信号线传输。不同报文通过 ID 区分，并通过仲裁机制决定发送优先级，通常 ID 数值越小，优先级越高。CAN 还支持 CRC 校验、错误检测和自动重发，可靠性比较好。使用时还需要 CAN 收发器和终端电阻。
```

3、IIC
```
I²C 是同步串行、半双工通信，通过 SCL 和 SDA 两根信号线通信，可以连接多个设备。主机通过 START 发起通信，发送从机地址和读写位，从机应答后传输数据，最后通过 STOP 结束。I²C 使用开漏输出，所以总线需要上拉电阻。
```

4、SPI
**SPI 是怎么传输的？**
```
SPI 是同步全双工通信。主机先通过 CS 选中从机，然后产生 SCK 时钟，MOSI 用来主机发送，MISO 用来主机接收。本质上双方通过移位寄存器，在每个时钟下逐位移出和移入数据，所以发送和接收可以同时进行。通信双方还要约定 CPOL、CPHA 和 MSB/LSB 位序。
```
**SPI 四种模式是什么？**
```
四种模式由 CPOL 和 CPHA 两位组合出来。CPOL 决定 SCK 空闲电平，0 是低、1 是高(空闲时候是高还是低)；CPHA 决定在哪个时钟边沿采样，0 是第一个边沿采样，1 是第二个边沿采样，所以组合起来就是 Mode 0 到 Mode 3。
```
`CS 选从机，SCK 提供时钟，MOSI/MISO 负责双向数据；CPOL/CPHA 决定时钟模式；MSB/LSB 决定从高位还是低位开始传。`

6、ADC
**我看你项目中用过 STM32F103 的 ADC。你能讲一下 ADC 是怎么把外部模拟电压转换成数字量的吗？尤其是你用的 12 位逐次逼近型 ADC，它内部具体是怎么工作的？**
```
STM32F103 使用的是 12 位逐次逼近型 ADC，主要用于把外部模拟电压转换成 0～4095 的数字量。
首先是采样阶段，ADC 内部会接通采样开关，让外部电压给内部的采样电容充电。经过一定的采样时间，电容上的电压足够接近输入电压，然后断开采样开关，保持这个电压。
接下来进入逐次逼近转换阶段。ADC 内部通过 DAC 产生一个已知的试探电压，再通过比较器判断输入电压和试探电压的大小。
它会从最高位开始尝试，每次比较确定一个二进制位。例如参考电压是 3.3V 时，第一次试探电压是 1.65V，然后根据比较结果继续确定后面的位。
12 位 ADC 经过逐位比较，最终得到一个 0～4095 的数字结果，CPU 可以通过数据寄存器读取，再根据参考电压换算成实际电压。
```
`DAC（数模转换器）：根据输入的数字编码，产生对应的模拟电压`

**假设 STM32 ADC 的参考电压是 3.3V，PA0 输入电压是 2.2V。**
```
首先，ADC 内部的逐次逼近逻辑会把 12 位数字的最高位尝试设置为 1，其余位设置为 0，也就是 1000 0000 0000，对应十进制的 2048。
内部 DAC 根据这个数字和参考电压，产生一个 1.65V 的试探电压。
然后比较器比较外部输入电压和内部试探电压。因为 2.2V 大于 1.65V，所以保留最高位的 1。
接下来，逐次逼近逻辑会尝试把第二位也设置为 1，形成 `1100 0000 0000`，内部 DAC 产生 2.475V。
由于 2.2V 小于 2.475V，所以第二位清零。
后面继续从高位到低位依次尝试，每次通过比较器判断当前位应该保留还是清零。
最终经过 12 次逐位比较，得到一个 12 位数字结果。整个过程由 ADC 内部硬件完成，不需要 CPU 自己计算。
```
**我看你在 STM32F103 项目中使用了 ADC。请问 ADC 的采样时间是什么意思？为什么采样时间不能设置得越短越好？另外，假设你把采样时间从 55.5 个周期改为 1.5 个周期，可能会出现什么问题？**
```
ADC 的采样时间，是指每次转换前，内部采样开关闭合，让外部模拟信号给采样电容充电或放电的时间。
因为充放电需要一定时间，所以必须让电容上的电压足够接近真实输入电压，才能保证后续转换的准确性。
这个过程会受到外部源阻抗的影响，源阻抗越大，通常电容充放电越慢，需要的采样时间就越长。
如果把采样时间从 55.5 个周期缩短到 1.5 个周期，虽然 ADC 的转换速度会提高，但可能造成采样电容还没稳定就开始转换，从而导致测量误差。因此实际开发中，需要根据外部源阻抗和转换速度要求，选择合适的采样时间，并不是越短越好。
```
**ADC 采样后传上去的是什么数据？**
```
ADC 采样并完成转换后，传递的是数字量，而不是原始模拟信号。
例如 STM32F103 使用 12 位 ADC，转换结果范围是 0～4095，存放在 ADC 数据寄存器中。
CPU 可以直接读取这个数字，也可以通过 DMA 将数据搬运到内存。
如果需要得到实际电压，就根据 ADC 参考电压进一步换算。
如果是通过串口等接口上传数据，那么具体传输原始 ADC 数值还是换算后的电压值，要看通信协议的设计。
```
