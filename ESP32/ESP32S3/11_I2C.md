# I2C

I2C 这一章先把电平和时序弄清楚，再看 ESP-IDF 的命令链。课程使用的是 v5.1.2 的 `driver/i2c.h` 接口。

## 电气

所有设备的 SCL 并在一起、SDA 并在一起；SCL / SDA 都是 **开漏输出 + 上拉电阻（PPT约 4.7 kΩ）**。

![[assets/ppt_111.png|900]]

*PPT：I2C 多设备并联、开漏、上拉。*

开漏最关键的规则：**输出 0 = 主动把线拉低；输出 1 = 高阻态，自己不拉高，由上拉电阻把总线拉高。** 因此任意一个器件拉低，总线就是低；只有所有器件都释放，总线才是高。

总线空闲时：**SCL=1，SDA=1**。

## START / STOP

I2C 普通数据传输遵循：**SCL 低电平期间允许 SDA 改变；SCL 高电平期间 SDA 应保持稳定。** START / STOP 故意利用 SCL 高时 SDA 的变化作为特殊标志。

**START：SCL=1 时，SDA 1→0。**  
**STOP：SCL=1 时，SDA 0→1。**

![[assets/ppt_112.png|900]]

*PPT：起始条件与终止条件。*

所以看到逻辑分析仪波形时，不要只盯 SDA 上升下降；必须同时看那一刻 SCL 是高还是低。

## 发送字节

发送 1 bit 的节奏：**SCL 拉低 → 主机把下一位放到 SDA → SCL 拉高 → 从机在高电平阶段读取 → SCL 再拉低。**

一个字节高位先行 B7→B0，重复 8 次。

![[assets/ppt_113.png|900]]

*PPT：主机发送一个字节，SCL 低时放数据，高时从机读取。*

## 接收字节

角色反过来：主机在开始接收前必须 **释放 SDA**；从机在 SCL 低电平期间准备数据，主机在 SCL 高电平期间读取。

![[assets/ppt_114.png|900]]

*PPT：从机放数据、主机读取一个字节。*

因此“释放 SDA”不是读到了 1，而是主机放弃对 SDA 的下拉控制，让从机真正决定电平。

## ACK / NACK

每传完 8 bit 后，第 9 个时钟是应答位。

**ACK = 0；NACK = 1。**

主机发完一个字节后要释放 SDA，在第 9 个 SCL 高电平读从机；主机接收完一个字节后，则由主机在第 9 个时钟把 SDA 拉成 0/1 给从机应答。

![[assets/ppt_115.png|900]]

*PPT：发送应答 / 接收应答。*

## 三种时序

### 主写

**S → Address|W → ACK → Data → ACK → P**

![[assets/ppt_116.png|900]]

*PPT：主机向从机发送数据。*

### 主读

**S → Address|R → ACK → Data → ACK → … → Data → NACK → P**

连续读取时，中间字节回 ACK 表示继续；最后一个字节回 NACK 表示“读完了”。

![[assets/ppt_117.png|900]]

*PPT：主机从从机读取多个字节，最后 NACK。*

### 写后读

很多传感器需要先发命令 / 寄存器，再立即读结果：

**S → Address|W → ACK → Data → ACK → S → Address|R → ACK → Data → NACK → P**

![[assets/ppt_118.png|900]]

*PPT：先写后读的组合事务。*

这里第二个 `start` 就是重复起始，目的不是结束通信，而是 **不释放总线就切换通信方向**。

## 地址

PPT 用 BH1750 演示 7 位设备地址与 R/W 位组合后的地址字节：写地址 `0x46`，读地址 `0x47`。两者只有最低位不同：0 表示写，1 表示读。

![[assets/ppt_119.png|900]]

*PPT：Address|W 与 Address|R 的构成。*

## I2C 外设

ESP32-S3 内部有 I2C0 / I2C1 两个控制器，支持主/从、7/10 位地址、100 kHz 与 400 kHz 等速度。硬件把 START、WRITE、READ、STOP 等动作组织成命令并由控制器执行。

![[assets/ppt_121.png|900]]

*PPT：I2C 控制器内部框图。*

![[assets/ppt_122.png|900]]

*PPT：I2C 命令控制器、数据转换器和 GPIO Matrix。*

课程 v5.1.2 的配置顺序：

**`i2c_param_config()` → `i2c_driver_install()` → `i2c_cmd_link_create()` → 把 START/WRITE/READ/STOP 依次加入命令链 → `i2c_master_cmd_begin()` 执行 → `i2c_cmd_link_delete()` 释放。**

![[assets/ppt_123.png|900]]

*PPT：I2C 命令链 API。*

视频工程的初始化代码原样如下：

**源码：`v5.1.2/14_IICBH1750/components/IIC/iic.c`**

```c
#include "iic.h"
#include "driver/gpio.h"
#include "driver/i2c.h"

void iic_init(void)
{
    i2c_config_t i2c_structure = {
        .clk_flags = 0,
        .master.clk_speed = 100000,
        .mode = I2C_MODE_MASTER,
        .scl_io_num = GPIO_NUM_4,
        .scl_pullup_en = GPIO_PULLUP_ENABLE,
        .sda_io_num = GPIO_NUM_5,
        .sda_pullup_en = GPIO_PULLUP_ENABLE,
    };
    i2c_param_config(I2C_NUM_0, &i2c_structure);

    i2c_driver_install(I2C_NUM_0, I2C_MODE_MASTER, 0, 0, 0);
}
```

这门课没有在这里写 GPIO bit-bang 软件 I2C；实验直接使用 ESP-IDF 的硬件 I2C 驱动，所以笔记也不额外塞一套自己编的软件 I2C 代码。

**源码工程：`14_IICBH1750`；PPT 页：108~123。**
