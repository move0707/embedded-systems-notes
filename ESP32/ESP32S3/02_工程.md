# 工程

## 配置

新工程不只是建一个 `main.c`。课程在创建工程后还会配置芯片相关选项：**Serial Flasher config → 外部 Flash；ESP PSRAM → PSRAM；ESP System Settings → CPU/系统；FreeRTOS → Tick 等参数。**

![[assets/ppt_029.png|900]]

*PPT：新建工程时的芯片配置入口。*

课程环境基于 ESP-IDF v5.1.2。安装阶段 PPT 特别提到两个环境变量：`IDF_PATH` 指向 ESP-IDF framework，`IDF_TOOLS_PATH` 指向工具链相关目录；VS Code 再通过 ESP-IDF 插件使用这些底层工具。

ESP-IDF 工程最外层 `CMakeLists.txt` 负责引入 IDF 构建系统，`main` 本身也是一个 component，自己写的 LED、KEY、SPI 等也可以放到 `components`。

## C 类型 / 结构体

课程在 GPIO 前专门补了 C 数据类型：`uint8_t`=8 bit 无符号、`uint16_t`=16 bit、`uint32_t`=32 bit、`int8_t/int16_t/int32_t` 为对应有符号类型；`float` 32 bit、`double` 64 bit。后面的 GPIO、ADC、PWM、通信缓冲区都会频繁使用这些定宽类型。

ESP-IDF 驱动大量使用结构体初始化，例如 `gpio_config_t cfg = { .mode = ..., .pin_bit_mask = ... };`。点号成员初始化的意义是“只看字段名就知道参数在配置什么”，并且不依赖结构体字段书写顺序。

## Hello World

课程代码同时演示 `printf()`、`ESP_LOGI()`、`ESP_LOGE()`。这里保持源码原样：

**源码：`v5.1.2/0_HelloWorld/main/main.c`**

```c
#include <stdio.h>
#include "freertos/FreeRTOS.h"
#include "freertos/task.h"
#include "esp_log.h"

static const char * TAG1 = "INFO";
static const char * TAG2 = "ERR";

void app_main(void)
{
    while (1)
    {
        printf("This is printf!\r\n");
        ESP_LOGI(TAG1,"This is an information!\r\n");
        ESP_LOGE(TAG2,"This is an error!\r\n");
        vTaskDelay(500);
    }
}
```

源码里直接写 `vTaskDelay(500)`；课程实验按默认配置把它作为约 500 ms 的周期使用。后面 GPIO、按键、PWM 等工程也大量使用 FreeRTOS 的 Delay。

## Component

`components/CMakeLists.txt` 决定哪些目录作为源文件、头文件目录和依赖组件参与编译。LED 工程原始配置：

**源码：`v5.1.2/1_LED/components/CMakeLists.txt`**

```cmake
set(src_dirs
            LED)

set(include_dirs
            LED)

set(requires
            driver)

idf_component_register(SRC_DIRS ${src_dirs} INCLUDE_DIRS ${include_dirs} REQUIRES ${requires})

component_compile_options(-ffast-math -O3 -Wno-error=format=-Wno-format)
```

理解成：**工程 → main + 自定义 components + ESP-IDF 官方 components → CMake 统一构建。**

**源码工程：`0_HelloWorld`、`1_LED`；PPT 页：27~29、41。**
