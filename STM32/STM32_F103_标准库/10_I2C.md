# I2C

I2C 这一章最容易乱。先只记一个总原则：

**SCL 低电平期间允许 SDA 改变；SCL 高电平期间 SDA 应保持稳定。**

START / STOP 是故意在 **SCL 高电平期间改变 SDA**，所以接收方能把它们和普通数据区分开。

## 总线

| I2C 通信 | I2C 硬件电路 |
|---|---|
| ![[assets/ppt/s127_I2C通信.jpg]] | ![[assets/ppt/s128_硬件电路.jpg]] |

I2C 两根线：

- `SCL`：时钟
- `SDA`：双向数据

所有设备的 SCL 并在一起，SDA 并在一起；两根线都需要上拉。

GPIO 使用 **开漏** 的原因：

**输出 0 → 主动拉低；输出 1 → 关闭下拉管，释放总线。**

只要任何一个器件拉低，总线就是低；只有所有器件都释放，上拉电阻才把线路拉高。

所以 I2C 空闲时：

**SCL=1，SDA=1**

## START / STOP

![[assets/ppt/s129_起始条件：SCL高电平期间，SDA从高电平切换到低电平.jpg]]

*起始与终止条件。*

### START

**SCL=1 时，SDA：1 → 0**

软件时序代码里的动作顺序：

**先释放 SDA → 释放 SCL → SDA 拉低 → SCL 拉低**

前两步先保证总线处于空闲高高状态；第三步才真正制造 START；最后把 SCL 拉低，准备发送第 1 位数据。

### STOP

**SCL=1 时，SDA：0 → 1**

顺序：

**先把 SDA 拉低 → SCL 拉高 → SDA 释放变高**

> [!important]
> 普通数据期间 SCL 高时不能随便改 SDA，否则就可能被解释成 START 或 STOP。

## 发送字节

![[assets/ppt/s130_发送一个字节：SCL低电平期间，主机将数据位依次放到SDA线上（高位先.jpg]]

*发送一个字节：高位先行。*

每一位都按同一节奏：

**SCL=0 → 主机设置 SDA → SCL=1 → 从机采样 SDA → SCL=0**

### 发 0

**SCL 低时 SDA 拉低 → SCL 拉高 → 从机读到 0**

### 发 1

**SCL 低时释放 SDA → 上拉使 SDA=1 → SCL 拉高 → 从机读到 1**

8 位按 **B7 → B6 → … → B0** 发送。

课程源码完全按这个动作写：

```c
for (i = 0; i < 8; i ++)
{
    MyI2C_W_SDA(!!(Byte & (0x80 >> i)));
    MyI2C_W_SCL(1);
    MyI2C_W_SCL(0);
}
```

其中 `!!(...)` 把“非 0”统一变成 1。

## 接收字节

![[assets/ppt/s131_接收一个字节：SCL低电平期间，从机将数据位依次放到SDA线上（高位先.jpg]]

*接收一个字节：主机先释放 SDA，从机在 SCL 低时准备数据，主机在 SCL 高时读取。*

主机接收前必须：

**SDA=1 → 释放 SDA**

之后每一位：

**SCL=0 时从机准备 SDA → 主机把 SCL 拉高 → 主机读 SDA → SCL 拉低**

课程源码：

```c
MyI2C_W_SDA(1);

for (i = 0; i < 8; i ++)
{
    MyI2C_W_SCL(1);

    if (MyI2C_R_SDA())
    {
        Byte |= (0x80 >> i);
    }

    MyI2C_W_SCL(0);
}
```

这里 `MyI2C_W_SDA(1)` 不是“主机给从机发送数据 1”，而是 **主机退出对 SDA 的拉低控制，让从机有机会驱动这根线**。

## ACK / NACK

![[assets/ppt/s132_发送应答：主机在接收完一个字节之后，在下一个时钟发送一位数据，数据0表.jpg]]

*发送/接收应答。第 9 个时钟传 ACK/NACK。*

每发完 8 位，紧接着第 9 个时钟传 1 位应答：

**ACK = 0**  
**NACK = 1**

### 主机发送 → 从机应答

主机发完 8 位后释放 SDA：

**主机释放 SDA → 第 9 个 SCL 拉高 → 主机读取 SDA**

如果从机把 SDA 拉低，就是 ACK。

### 从机发送 → 主机应答

主机收完 8 位后主动给第 9 位：

- 还要继续读：主机拉低 SDA，发 ACK
- 最后一个字节：主机释放 SDA，发 NACK

所以“ACK 谁来发”取决于 **当前 8 位数据是谁接收的**。

## 三种时序

课程 10-1 明确讲 3 种完整时序。

| 指定地址写 | 当前地址读 |
|---|---|
| ![[assets/ppt/s133_I2C时序.jpg]] | ![[assets/ppt/s134_I2C时序.jpg]] |

| 指定地址读 |
|---|
| ![[assets/ppt/s135_I2C时序.jpg]] |

### 指定地址写

目标：给指定设备的指定寄存器写数据。

**S → Slave+W → ACK → Reg → ACK → Data → ACK → P**

例如 MPU6050：

`Slave = 0xD0`（课程源码直接使用已经包含写位的 8 位地址）

`Reg = 某个寄存器地址`

`Data = 要写的值`

含义：

**先呼叫设备 → 告诉它“我要写” → 指定内部寄存器 → 写数据**

### 当前地址读

目标：不重新发寄存器地址，直接从从机当前地址指针处读取。

**S → Slave+R → ACK → Data → NACK → P**

关键点：这里没有 `Reg`，因此读的是设备内部“当前地址指针”指向的位置。

### 指定地址读

目标：读指定寄存器。

**S → Slave+W → ACK → Reg → ACK → Sr → Slave+R → ACK → Data → NACK → P**

最关键的一点：

**明明是“读”，为什么前半段先写？**

因为主机要先把 `Reg` 告诉从机，先把内部地址指针放到指定寄存器；然后用 **重复起始 Sr** 重新寻址，把方向切换成读。

所以可以记成：

**指定地址读 = “写寄存器地址” + “重复起始” + “当前地址读”**

## 地址

I2C 常说 7 位设备地址，但课程软件 I2C 源码对 MPU6050 定义的是：

```c
#define MPU6050_ADDRESS  0xD0
```

这是把 7 位地址左移 1 位之后，把最低位留给 R/W 的 **8 位地址写法**。

因此课程代码里：

**写地址：`0xD0`**  
**读地址：`0xD0 | 0x01 = 0xD1`**

不要把“7 位地址”和“总线上实际发送的地址字节”混在一起。

## 软件 I2C

软件 I2C 完全用 GPIO 模拟时序。

底层只有 3 个最原始动作：

**写 SCL → 写 SDA → 读 SDA**

再组合出：

**Start → Stop → SendByte → ReceiveByte → SendAck → ReceiveAck**

GPIO 配置：

**PB10=SCL，PB11=SDA，`GPIO_Mode_Out_OD`**

> [!code]- 视频源码：MyI2C.c
> ```c
> #include "stm32f10x.h"                  // Device header
> #include "Delay.h"
> 
> /*引脚配置层*/
> 
> /**
>   * 函    数：I2C写SCL引脚电平
>   * 参    数：BitValue 协议层传入的当前需要写入SCL的电平，范围0~1
>   * 返 回 值：无
>   * 注意事项：此函数需要用户实现内容，当BitValue为0时，需要置SCL为低电平，当BitValue为1时，需要置SCL为高电平
>   */
> void MyI2C_W_SCL(uint8_t BitValue)
> {
> 	GPIO_WriteBit(GPIOB, GPIO_Pin_10, (BitAction)BitValue);		//根据BitValue，设置SCL引脚的电平
> 	Delay_us(10);												//延时10us，防止时序频率超过要求
> }
> 
> /**
>   * 函    数：I2C写SDA引脚电平
>   * 参    数：BitValue 协议层传入的当前需要写入SDA的电平，范围0~1
>   * 返 回 值：无
>   * 注意事项：此函数需要用户实现内容，当BitValue为0时，需要置SDA为低电平，当BitValue为1时，需要置SDA为高电平
>   */
> void MyI2C_W_SDA(uint8_t BitValue)
> {
> 	GPIO_WriteBit(GPIOB, GPIO_Pin_11, (BitAction)BitValue);		//根据BitValue，设置SDA引脚的电平，BitValue要实现非0即1的特性
> 	Delay_us(10);												//延时10us，防止时序频率超过要求
> }
> 
> /**
>   * 函    数：I2C读SDA引脚电平
>   * 参    数：无
>   * 返 回 值：协议层需要得到的当前SDA的电平，范围0~1
>   * 注意事项：此函数需要用户实现内容，当前SDA为低电平时，返回0，当前SDA为高电平时，返回1
>   */
> uint8_t MyI2C_R_SDA(void)
> {
> 	uint8_t BitValue;
> 	BitValue = GPIO_ReadInputDataBit(GPIOB, GPIO_Pin_11);		//读取SDA电平
> 	Delay_us(10);												//延时10us，防止时序频率超过要求
> 	return BitValue;											//返回SDA电平
> }
> 
> /**
>   * 函    数：I2C初始化
>   * 参    数：无
>   * 返 回 值：无
>   * 注意事项：此函数需要用户实现内容，实现SCL和SDA引脚的初始化
>   */
> void MyI2C_Init(void)
> {
> 	/*开启时钟*/
> 	RCC_APB2PeriphClockCmd(RCC_APB2Periph_GPIOB, ENABLE);	//开启GPIOB的时钟
> 	
> 	/*GPIO初始化*/
> 	GPIO_InitTypeDef GPIO_InitStructure;
> 	GPIO_InitStructure.GPIO_Mode = GPIO_Mode_Out_OD;
> 	GPIO_InitStructure.GPIO_Pin = GPIO_Pin_10 | GPIO_Pin_11;
> 	GPIO_InitStructure.GPIO_Speed = GPIO_Speed_50MHz;
> 	GPIO_Init(GPIOB, &GPIO_InitStructure);					//将PB10和PB11引脚初始化为开漏输出
> 	
> 	/*设置默认电平*/
> 	GPIO_SetBits(GPIOB, GPIO_Pin_10 | GPIO_Pin_11);			//设置PB10和PB11引脚初始化后默认为高电平（释放总线状态）
> }
> 
> /*协议层*/
> 
> /**
>   * 函    数：I2C起始
>   * 参    数：无
>   * 返 回 值：无
>   */
> void MyI2C_Start(void)
> {
> 	MyI2C_W_SDA(1);							//释放SDA，确保SDA为高电平
> 	MyI2C_W_SCL(1);							//释放SCL，确保SCL为高电平
> 	MyI2C_W_SDA(0);							//在SCL高电平期间，拉低SDA，产生起始信号
> 	MyI2C_W_SCL(0);							//起始后把SCL也拉低，即为了占用总线，也为了方便总线时序的拼接
> }
> 
> /**
>   * 函    数：I2C终止
>   * 参    数：无
>   * 返 回 值：无
>   */
> void MyI2C_Stop(void)
> {
> 	MyI2C_W_SDA(0);							//拉低SDA，确保SDA为低电平
> 	MyI2C_W_SCL(1);							//释放SCL，使SCL呈现高电平
> 	MyI2C_W_SDA(1);							//在SCL高电平期间，释放SDA，产生终止信号
> }
> 
> /**
>   * 函    数：I2C发送一个字节
>   * 参    数：Byte 要发送的一个字节数据，范围：0x00~0xFF
>   * 返 回 值：无
>   */
> void MyI2C_SendByte(uint8_t Byte)
> {
> 	uint8_t i;
> 	for (i = 0; i < 8; i ++)				//循环8次，主机依次发送数据的每一位
> 	{
> 		/*两个!可以对数据进行两次逻辑取反，作用是把非0值统一转换为1，即：!!(0) = 0，!!(非0) = 1*/
> 		MyI2C_W_SDA(!!(Byte & (0x80 >> i)));//使用掩码的方式取出Byte的指定一位数据并写入到SDA线
> 		MyI2C_W_SCL(1);						//释放SCL，从机在SCL高电平期间读取SDA
> 		MyI2C_W_SCL(0);						//拉低SCL，主机开始发送下一位数据
> 	}
> }
> 
> /**
>   * 函    数：I2C接收一个字节
>   * 参    数：无
>   * 返 回 值：接收到的一个字节数据，范围：0x00~0xFF
>   */
> uint8_t MyI2C_ReceiveByte(void)
> {
> 	uint8_t i, Byte = 0x00;					//定义接收的数据，并赋初值0x00，此处必须赋初值0x00，后面会用到
> 	MyI2C_W_SDA(1);							//接收前，主机先确保释放SDA，避免干扰从机的数据发送
> 	for (i = 0; i < 8; i ++)				//循环8次，主机依次接收数据的每一位
> 	{
> 		MyI2C_W_SCL(1);						//释放SCL，主机机在SCL高电平期间读取SDA
> 		if (MyI2C_R_SDA()){Byte |= (0x80 >> i);}	//读取SDA数据，并存储到Byte变量
> 													//当SDA为1时，置变量指定位为1，当SDA为0时，不做处理，指定位为默认的初值0
> 		MyI2C_W_SCL(0);						//拉低SCL，从机在SCL低电平期间写入SDA
> 	}
> 	return Byte;							//返回接收到的一个字节数据
> }
> 
> /**
>   * 函    数：I2C发送应答位
>   * 参    数：Byte 要发送的应答位，范围：0~1，0表示应答，1表示非应答
>   * 返 回 值：无
>   */
> void MyI2C_SendAck(uint8_t AckBit)
> {
> 	MyI2C_W_SDA(AckBit);					//主机把应答位数据放到SDA线
> 	MyI2C_W_SCL(1);							//释放SCL，从机在SCL高电平期间，读取应答位
> 	MyI2C_W_SCL(0);							//拉低SCL，开始下一个时序模块
> }
> 
> /**
>   * 函    数：I2C接收应答位
>   * 参    数：无
>   * 返 回 值：接收到的应答位，范围：0~1，0表示应答，1表示非应答
>   */
> uint8_t MyI2C_ReceiveAck(void)
> {
> 	uint8_t AckBit;							//定义应答位变量
> 	MyI2C_W_SDA(1);							//接收前，主机先确保释放SDA，避免干扰从机的数据发送
> 	MyI2C_W_SCL(1);							//释放SCL，主机机在SCL高电平期间读取SDA
> 	AckBit = MyI2C_R_SDA();					//将应答位存储到变量里
> 	MyI2C_W_SCL(0);							//拉低SCL，开始下一个时序模块
> 	return AckBit;							//返回定义应答位变量
> }
> ```

### 为什么开漏还能读

开漏输出写 1 时，引脚不是被强推成高，而是变成高阻态；此时引脚真实电平由上拉和从机共同决定，所以仍然可以用 `GPIO_ReadInputDataBit()` 读取 SDA。

## 硬件 I2C

| I2C 框图 | I2C 基本结构 |
|---|---|
| ![[assets/ppt/s141_I2C框图.jpg]] | ![[assets/ppt/s142_I2C基本结构.jpg]] |

硬件 I2C 的协议完全没变，变化的是：

**软件 I2C：CPU 每一位手动控制 SCL/SDA**  
**硬件 I2C：CPU 下发“START / 地址 / 数据 / STOP”等操作，I2C 外设自己产生位级波形**

GPIO 改为：

**`GPIO_Mode_AF_OD`**

因为 PB10/PB11 由 I2C2 外设接管。

### 主机发送

![[assets/ppt/s143_主机发送.jpg]]

*硬件 I2C 主机发送事件流程。*

课程代码按事件推进：

**Generate START → EV5 → Send Address(Tx) → EV6 → Send Reg/Data → EV8/EV8_2 → STOP**

事件的作用就是确认硬件已经走到指定阶段，再进行下一步。

### 主机接收

![[assets/ppt/s144_主机接收.jpg]]

*硬件 I2C 主机接收事件流程。*

指定寄存器读仍然是：

**START → Tx 地址 → Reg → ReSTART → Rx 地址 → 最后一个字节前关闭 ACK → STOP → EV7 → 读 DR**

课程硬件 I2C 源码中，单字节接收前会：

```c
I2C_AcknowledgeConfig(I2C2, DISABLE);
I2C_GenerateSTOP(I2C2, ENABLE);
```

然后等待 EV7、读取数据，再恢复 ACK。这个顺序是为了告诉从机“只收这一个字节，后面结束”。

## 波形对比

![[assets/ppt/s145_软件_硬件波形对比.jpg]]

*课程软件 I2C / 硬件 I2C 波形对比。*

协议层看到的 START、地址、数据、ACK、STOP 应该一致；区别只是“谁负责逐位产生波形”。

## 易错

| 现象 | 优先检查 |
|---|---|
| 总线一直高 | 从机没响应、地址错、线路断开 |
| 总线一直低 | SDA/SCL 被器件持续拉低、接线/供电问题 |
| 没有 START | SCL 高期间 SDA 没有 1→0 |
| 一直 NACK | 地址、供电、上拉、设备状态、SCL/SDA 接反 |
| 读到 0xFF | SDA 很可能一直被释放为高 |
| 读到 0x00 | SDA 很可能一直被拉低 |
| 软件 I2C 正常、硬件不正常 | GPIO 应为 AF_OD、I2C2 时钟/参数、事件流程 |
| 指定读错寄存器 | Reg 没正确写入，或者重复起始/读方向错误 |

## 速记

**空闲：高高**  
**数据：低时改，高时读**  
**START：SCL 高时 SDA 下降**  
**STOP：SCL 高时 SDA 上升**  
**ACK：第 9 个时钟 SDA=0**  
**指定读：先写 Reg，再 Sr 切读**
